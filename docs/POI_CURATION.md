# POI 策展规范

## 数据身份

- `mock` 记录只用于单元测试和前端开发，ID 必须以 `mock_` 开头。
- 当前项目暂时全部使用固定 Mock POI，以便路线、剧情、地图适配、状态机、离线存储和 API 开发持续进行。
- 正式模式只能读取 `verificationStatus: verified` 的记录。
- AI 不得创建正式 POI，也不得把 `mock`、`pending` 或 `unverified` 记录提升为 `verified`。
- Mock 数据不代表真实地点已经核验，不得用于真实线下导航。

## 内容模式

服务端使用 `APP_CONTENT_MODE=mock | verified` 选择内容：

- `mock` 只加载 `verificationStatus: mock` 的记录，用于本地开发、自动化测试和功能演示。
- `verified` 只加载 `verificationStatus: verified` 的记录。任一路线包数量不足时必须返回 `INSUFFICIENT_VERIFIED_POIS`，不得自动使用 Mock 数据。

业务模块只通过共享 `PoiSchema` 和 POI ID 使用地点数据，不得把具体地点名称写进路线算法、Story Graph、地图适配、状态机、离线存储或 CloudBase API 逻辑。

## 人工核验流程

1. 策展人员从公开、可核验的来源提出候选 POI，并先标记为 `unverified`。
2. 在腾讯地图核对地点名称、地址、公众可达性和坐标，记录来源 URL。
3. 人工检查步行入口、停留空间、费用、安全提示、观察锚点、任务钩子与备用节点。
4. 现场复核公共访问条件；不得把需要进入私人住宅的内容纳入路线。
5. 由另一名审核者复核数据和证据。全部通过后才能填写 `verifiedAt` 并标记为 `verified`。
6. 运行 `npm run content:validate`，校验报告无错误后才可进入正式数据发布流程。

## 腾讯地图坐标

- 在腾讯地图中定位公开地点，从地点详情或经纬度拾取工具获取 GCJ-02 坐标。
- 记录地点公开入口或实际集合点坐标，不使用建筑几何中心代替可达入口。
- 导入前核对经纬度顺序；上海数据还必须通过项目配置的合理范围检查。
- 坐标来源和核验日期写入策展工作记录，不从 Google 或 Mapbox 转换坐标。

## `sourceUrls` 记录规范

- `verified` 记录至少提供一个可访问的来源 URL。
- 优先使用场地方、政府部门、公共文化机构或腾讯地图地点页等一手来源。
- 来源应能支持地点存在性、公众可达性或地点信息，不使用搜索结果页作为证据。
- 多个事实来自不同页面时分别记录，不把 URL 写入故事文案字段。

## 开放时间

路线内容不写死容易变化的开放时间。可以提示用户出发前查看官方渠道，并在运行时展示“开放情况以现场及官方最新信息为准”。确需保存开放信息时，应存为带来源和复核时间的独立可更新数据，而不是写进剧情。

## 现场实际情况

施工、活动管制、天气、临时闭馆和公共空间管理都可能改变可达性。产品必须提醒用户以现场标识和工作人员要求为准，不翻越围挡、不阻塞通行、不进入非公开区域，也不设置拍摄陌生人正脸的任务。

## 复核周期

- 正式 POI 至少每 90 天复核一次。
- 涉及收费、临时展览、施工或访问条件变化的 POI，应缩短周期并在变化后立即复核。
- 来源失效、现场反馈异常或备用节点不可用时，立即降级为 `pending`，复核前不进入正式路线。

## 备用节点

- 每个 POI 至少配置一个同路线包内的备用 POI，且不能引用自身。
- 备用节点应满足相近时长、公众可达和安全条件，不能依赖同一处可能关闭的入口。
- 导入器会检查引用存在性；路线运行时应优先选择 `verified` 备用节点。
- `mock` 备用关系只用于开发，不得进入正式模式。

## 正式发布门槛

正式发布前必须完成真实 POI 核验、地址与坐标确认、腾讯地图路线联调、任务和备用节点现场验证，以及至少一次完整实地走测。详细阻塞项见 [`RELEASE_BLOCKERS.md`](RELEASE_BLOCKERS.md)。
